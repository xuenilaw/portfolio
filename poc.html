Proof of Concept — Appium Test Automation in Android Automotive

Overview

  • Goal: This proof of concept demonstrates UI test automation for Android Automotive using Appium. The main objective is to show that critical infotainment and navigation interactions—such as touch input, screen navigation, and search-related UI flows—can be exercised and checked repeatably on an automotive Android target under conditions close to real in-vehicle use.
  • What the demo shows: The recording walks through an automated UI test run against an Android Automotive environment (emulator or device). Appium drives the UI: the test launches the application, performs typical user actions (for example tapping controls, entering search input, navigating screens), and verifies expected UI outcomes—from test execution to visible results on the HMI.

    • Technology stack

  • Tool: Appium (mobile UI automation).
  • Target platform: Android Automotive.
  • Scope: UI test automation (UI TA) for HMI and navigation-style applications.
  • Purpose: Proof of automation feasibility alongside manual and system-level testing.

    • Demo video

    Why Appium?

  • Platform fit: Appium is widely used for Android UI automation and maps well to touch-based automotive HMIs.
  • Skill reuse: Complements broader automation work (for example Robot Framework on the web PoC) and shows a path from web to in-vehicle UI testing.
  • Stakeholder value: A short demo makes automation tangible for teams evaluating test strategy for complex navigation systems.
